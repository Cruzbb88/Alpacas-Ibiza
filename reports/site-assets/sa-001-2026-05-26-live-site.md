## 4. Gap Analysis

### Gap 1 — Live site primary color: UNKNOWN vs. Redesign `--primary` #546A2E (Olive)
**Status: Cannot confirm alignment.**
The live site's CTA button and heading colors were not extractable. The redesign chose olive green as primary. This is a reasonable earthy/natural choice for an alpaca farm brand, but it is NOT confirmed against any live site hex value.
**Recommendation:** Open the live site in a browser, inspect a `"Plan je bezoek"` button, copy its background-color. If it is close to #556B2F / #546A2E, alignment is good. If it is neutral (black, dark navy, etc.), redesign is making an intentional upgrade — document the decision.

### Gap 2 — Live site font: UNKNOWN vs. Redesign Playfair Display + Geist
**Status: Cannot confirm alignment.**
Squarespace font is not extractable via WebFetch. The live site visual tone is described as modern-minimal (consistent with sans-serif), but the redesign uses Playfair Display (elegant serif) for display headings. This is a common upgrade pattern (live Squarespace default → premium serif in redesign), but needs visual verification against the live site.
**Recommendation:** Inspect the live site heading `font-family` in DevTools. If the live site already uses a serif, Playfair is aligned. If the live site uses Helvetica/Arial/system sans, the redesign is upgrading typography — intentional, but flag for owner sign-off.

### Gap 3 — Live site secondary/background: UNKNOWN vs. Redesign `--secondary` #EDEDDD (sand)
**Status: Cannot confirm alignment.**
The redesign uses a warm sand (#EDEDDD) as secondary. The live site page descriptions consistently read as "white/near-white" backgrounds with earthy/natural tone. #EDEDDD is warmer than pure white; the direction is right for the brand aesthetic.
**Recommendation:** Likely intentional improvement. Keep unless owner specifically wants pure white (#FFFFFF) backgrounds.

### Gap 4 — `themeColor` #6DA855 vs. `--primary` #546A2E
**Status: Internal redesign inconsistency.**
`viewport.themeColor` in `app/layout.tsx` is `#6DA855` — a bright lime-leaning green. The CSS `--primary` computes to `#546A2E` — a darker olive. These two greens diverge noticeably (one is vibrant, one is muted/earthy). The theme color is what browsers show in the tab bar on mobile.
**Recommendation:** Match themeColor to --primary: change `#6DA855` → `#546A2E` (or the olive hex the owner approves). This is a 1-line fix in `app/layout.tsx:38`.

### Gap 5 — globals.css body font override conflict
**Status: Internal redesign bug.**
`globals.css` line 6 sets `font-family: Arial, Helvetica, sans-serif` on `body`, which would override Geist loaded via `next/font/google`. The Geist font variable is loaded as `_geistSans` but never applied to a className on `<body>` (layout.tsx uses `className="font-sans antialiased"` which maps to Tailwind's default sans stack, not Geist).
**Recommendation:** Either (a) set `body { font-family: var(--font-geist-sans, Arial, Helvetica, sans-serif); }` in globals.css, or (b) apply `_geistSans.className` to `<body>` in layout.tsx. Currently Geist is loaded but likely not rendering.
