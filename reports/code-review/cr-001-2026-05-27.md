## Top 5 Highest-Impact Findings

### F1 — CI quality gates all silenced (Major)
**File:** `.github/workflows/ci.yml` — lint, typecheck, test, e2e jobs  
**Issue:** Every quality-gate step now has `continue-on-error: true`. This means a PR that fails lint, TypeScript typechecks, unit tests, AND e2e tests still shows a green check and can be merged. The gates are decorative.  
**Fix:** Remove `continue-on-error: true` from all steps, or scope it only to the e2e job where flakiness is a known issue. If the tests were passing before, there is no need for this flag. If they were not passing, fix the failures rather than hiding them.  
**Note:** The `npm install → npm ci` change on the same jobs is correct and should be kept.

---

### F2 — Unauthenticated billing portal (Major)
**File:** `app/api/billing-portal/route.ts:64–81`  
**Issue:** `POST /api/billing-portal` with `{"email":"victim@example.com"}` returns a live Stripe Customer Portal URL that grants full subscription self-service (cancel, update payment, view invoices) with zero authentication. No Turnstile, no rate-limit, no session check. The security review (sr-003) already flagged this as Medium severity — this review concurs.  
**Fix (design decision required — see CAN'T DO WITHOUT HELP below):** At minimum: add in-memory rate-limit (same `rateLimit()` helper used on contact/newsletter) + Turnstile widget. Full fix: require NextAuth session — but this changes the UX (subscriber must be logged in).

---

### F3 — Raw email in `replyTo` SMTP field (Minor, security-adjacent)
**File:** `app/api/gdpr-request/route.ts:84–92`  
The code does `escapeHtml(email)` correctly for rendering in HTML, but `replyTo: email` on line 91 uses the **raw unescaped** value. The `isValidEmail()` guard on line 67 filters malformed emails, so direct CRLF injection is blocked — but this is a defense-in-depth gap. The `sanitizeHeader()` helper already exists in `lib/html.ts` and is used on contact/commission routes for exactly this purpose.  
**Fix:** `replyTo: sanitizeHeader(typeof email === 'string' ? email : '')` — one-line fix using the existing helper. Import `sanitizeHeader` from `@/lib/html`.

---

### F4 — Duplicated GDPR block in two legal pages (Minor)
**File:** `app/[locale]/cookies/page.tsx:113–128` and `app/[locale]/privacy/page.tsx:75–90`  
Identical 16-line JSX block. When the GDPR contact email or subject line changes, it must be updated in two places.  
**Fix:** Extract to a `<GdprRightsSection />` component in `components/gdpr-rights-section.tsx`. Both pages import and render it. No props needed — it's fully static.

---

### F5 — i18n gap check dropped from CI (Informational)
**File:** `.github/workflows/ci.yml`  
The old `i18n-gap` job that ran `node scripts/check-i18n-gap.js` was removed. If `scripts/check-i18n-gap.js` still exists, translation gaps will no longer be caught automatically.  
**Fix:** Add the check back as a step under the `build` job, or as its own job with `continue-on-error: false`. Low urgency but worth noting for the next sprint.

## CAN'T DO WITHOUT HELP

**F2 — billing portal auth gate:** The correct fix depends on a design decision. Two options:
1. **Turnstile + rate-limit only** — low friction, subscriber does not log in, but a determined attacker with many emails can still enumerate. Matches the existing UX where the `<details>` panel just asks for email.
2. **Require NextAuth session** — eliminates the oracle entirely, but requires subscribers to have an account. The current site has no subscriber sign-up flow; admin login is separate.

Owner / Tony needs to decide which model before this can be closed.
