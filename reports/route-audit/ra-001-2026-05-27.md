# Route Audit — ra-001 — 2026-05-27

**Scope:** Every `page.tsx` under `app/[locale]/` (17 files)
**Infrastructure check:** `loading.tsx`, `error.tsx`, `not-found.tsx` presence per route
**Cross-referenced with:** mr-001 pain scores, incompleteness-master, OWNER_INPUT_NEEDED

---

## Infrastructure gaps — site-wide

Before the per-route matrix, one finding applies universally and is worth calling out:

| Gap | Present | Notes |
|-----|---------|-------|
| `loading.tsx` (any route) | **NONE** | Zero `loading.tsx` files anywhere under `app/[locale]/`. Every async page renders with no skeleton. |
| `error.tsx` (any route) | **NONE** | Zero `error.tsx` files. Unhandled server component errors will bubble to `app/global-error.tsx` (which exists), but there is no route-level recovery. |
| `not-found.tsx` (locale root) | **1 — exists and complete** | `app/[locale]/not-found.tsx` is a full branded 404 with suggested pages. `[...slug]/page.tsx` correctly calls `notFound()` to trigger it. |
| `not-found.tsx` (per sub-route) | **NONE** | Sub-routes (experiences, shop/*) have no individual not-found pages — acceptable, they cascade to the locale root. |

**Impact:** Every server component page (18 of 17 routes are server components) has zero loading state and zero route-level error containment. Users on slow connections see a blank page while data fetches; a thrown error in any server component takes down the entire page with no graceful message.
