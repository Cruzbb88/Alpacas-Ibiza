# Mobile Responsiveness Audit — Alpacas Ibiza Redesign
**Report ID:** MA-001  
**Date:** 2026-05-27  
**Method:** Heuristic (static code analysis only — no live device or DevTools session)  
**Auditor:** Claude Code (Sonnet 4.6)

---

## Composite Mobile-Readiness Score: 7.1 / 10

Strong foundation: Tailwind mobile-first, Sheet-based hamburger menu, sticky booking bar (`md:hidden`), `flex-col sm:flex-row` patterns on CTAs. Breakage risks are concentrated in a few specific patterns — none are catastrophic, but two are above-the-fold on the highest-traffic pages.

---

## Viewport Configuration (app/layout.tsx)

```ts
export const viewport: Viewport = {
  width: 'device-width',
  initialScale: 1,
  maximumScale: 1,
  userScalable: false,   // ← PROBLEM
  themeColor: '#6da855',
}
```

`userScalable: false` blocks pinch-zoom. This is a WCAG 1.4.4 (Level AA) failure and a real usability problem on 375px viewports where text density is highest. Modern iOS and Android ignore this for accessibility reasons, but it remains a compliance issue and should be removed.

---

## Finding Inventory

### F-01 — userScalable: false (CRITICAL — a11y violation)
**File:** `app/layout.tsx:34`  
**Impact:** WCAG 1.4.4 fail. Blocks pinch-zoom on all viewports. Remove `userScalable: false` and `maximumScale: 1`.

---

### F-02 — Newsletter inline `flex` row breaks at 320px (HIGH)
**File:** `components/newsletter-form.tsx:62`  
```tsx
<div className="flex gap-2">
  <input className="flex-1 ..." />
  <button ...>Subscribe</button>
</div>
```
No `flex-col sm:flex-row` fallback. At 320px (iPhone SE), the input shrinks to ~200px and the subscribe button gets squeezed to near-unreadable. Fix: add `flex-col sm:flex-row` and give the button `w-full sm:w-auto`.

---

### F-03 — LanguageSwitcher fixed 140px width in mobile Sheet (MEDIUM)
**File:** `components/language-switcher.tsx:32`  
```tsx
<SelectTrigger className="w-[140px] border-border bg-background">
```
When the LanguageSwitcher appears in the mobile Sheet (inside header), the select trigger is hardcoded at 140px regardless of viewport. On 320px with Sheet padding this is ~40% of available width and clips the locale name. Fix: replace with `w-full sm:w-[140px]` — or just `w-full` inside the Sheet context.

---

### F-04 — Commission form card over-padded on mobile (MEDIUM)
**File:** `app/[locale]/shop/commission/page.tsx:35`  
```tsx
<div className="bg-card rounded-lg border border-border p-8 md:p-12">
```
`p-8` = 32px on mobile. On a 375px viewport that leaves only 311px of content width. With `max-w-4xl` the container fills the screen anyway, so the `p-8` is fine — but the inner form inputs with `px-4 py-2` + label `mb-2` stack comfortably. Acceptable, but worth monitoring if translation strings are long.

---

### F-05 — Booking section `grid-cols-2` date cards (MEDIUM)
**File:** `components/booking-section.tsx:43`  
```tsx
<div className="grid grid-cols-2 md:grid-cols-4 gap-4 max-w-3xl mx-auto mb-8">
```
`grid-cols-2` is intentional and fine for 375px+ — each card is ~150px wide. At 320px the gap + padding leaves ~120px per card; the `text-3xl` day number (`{formatted.day}`) may clip. Low risk but the `max-w-3xl` constraint means the grid won't stretch on large phones either.

---

### F-06 — Cookie consent button row not wrapping at 320px (MEDIUM)
**File:** `components/cookie-consent.tsx:83`  
```tsx
<div className="flex gap-2 shrink-0">
  <button ...>Reject non-essential</button>
  <button ...>Accept all</button>
</div>
```
`shrink-0` prevents the button row from shrinking. The container above uses `flex-col md:flex-row`, so on mobile these buttons are in a column of their own — good. But the "Reject non-essential" button label is 18+ chars and with `px-4 py-2` it can extend beyond 320px screen width without `w-full`. Fix: add `w-full` to both buttons (already column-stacked on mobile, so this is just visual hygiene).

---

### F-07 — Hero `min-h-[600px]` on 320px (LOW)
**File:** `components/hero.tsx:33`  
```tsx
className="relative w-full min-h-[600px] md:min-h-[700px] flex items-center ..."
```
600px minimum height is intentional for visual impact. On 320x568px (iPhone SE in portrait) the hero alone takes 600/568 = 105% of the visible viewport — content is below the fold immediately. Not a bug in the Tailwind sense, but users must scroll to reach any CTA. Consider `min-h-[90svh] md:min-h-[700px]` or `min-h-[500px] md:min-h-[700px]` to leave at least the CTA visible above the fold.

---

### F-08 — `about/page.tsx` herd grid collapses to 2 columns at 320px (LOW)
**File:** `app/[locale]/about/page.tsx:106`  
```tsx
<ul className="grid grid-cols-2 sm:grid-cols-3 md:grid-cols-4 lg:grid-cols-5 gap-3">
```
`grid-cols-2` at 320px = ~140px per name cell. Alpaca names (Barbarella, Avalon) with `p-4` are fine. Minor risk if a future long name is added.

---

### F-09 — FareHarbor embedded calendar: no mobile viewport instruction (LOW)
**File:** `components/fareharbor-calendar.tsx`  
The third-party FareHarbor calendar is injected via `<script>` and replaces the wrapper div. FareHarbor's own calendar widget is not always mobile-optimised. The wrapper has `w-full` which is correct. No code fix available on our side, but the `p-6 md:p-8` container around it on the tours page is correct. Document this as a third-party concern.

---

### F-10 — StickyBookingBar z-index vs CookieConsent stacking (LOW)
**File:** `components/sticky-booking-bar.tsx:32`, `components/cookie-consent.tsx:69`  
StickyBookingBar: `z-50`. CookieConsent: `z-[1000]`. Both pin to `bottom-0`. On mobile, when cookie consent is visible, the StickyBookingBar (`z-50`) renders beneath CookieConsent (`z-[1000]`) — the booking CTA is invisible until consent is resolved. This is actually the correct UX, but worth flagging: if cookie consent is dismissed, the sticky bar should reappear. Current logic handles this (`isVisible` state + scroll) but both compete for the same bottom space. Adequate.

## Top 10 Fixes (Ranked by Visibility)

1. **Remove `userScalable: false`** (`app/layout.tsx:34`) — WCAG 1.4.4 violation. Remove `userScalable: false` and `maximumScale: 1` from the viewport export. One-line fix, zero UI impact.

2. **Newsletter form: stack on mobile** (`components/newsletter-form.tsx:62`) — Change `flex gap-2` to `flex flex-col sm:flex-row gap-2`; add `w-full sm:w-auto` to the submit button.

3. **Hero min-height: reduce for smallest viewports** (`components/hero.tsx:33`) — Change `min-h-[600px]` to `min-h-[500px] sm:min-h-[600px]` so the hero CTA is partially visible above fold on 320-375px.

4. **LanguageSwitcher width: fluid in Sheet** (`components/language-switcher.tsx:32`) — Accept a `className` prop; in `header.tsx` pass `className="w-full"` when rendering inside the Sheet vs. default `w-[140px]` in the desktop nav.

5. **Cookie consent buttons: full-width on mobile** (`components/cookie-consent.tsx:83-103`) — Add `w-full sm:w-auto` to both buttons. The flex column layout already stacks them; this just prevents any overflow at 320px.

6. **Commission card padding: reduce mobile padding** (`app/[locale]/shop/commission/page.tsx:35`) — Change `p-8 md:p-12` to `p-4 sm:p-8 md:p-12` to recover ~16px per side at 375px.

7. **Booking date grid: verify 320px cards** (`components/booking-section.tsx:43`) — Add `text-2xl sm:text-3xl` to the day number to prevent clipping on smallest viewport.

8. **Home reviews grid: verify text-balance on long German reviews** (`app/[locale]/page.tsx:219`) — The `grid-cols-1 md:grid-cols-3` is correct. German reviews are long; verify `ReviewCard` uses `text-balance` or `leading-relaxed` and doesn't overflow its card boundary.

9. **About herd grid: guard against long names** (`app/[locale]/about/page.tsx:106`) — Add `break-words` or `truncate` to the alpaca name cells to future-proof against long names.

10. **Hero video: confirm `playsInline`** (`components/hero.tsx:38`) — Already present. iOS requires `playsInline` to autoplay inline (vs. full-screen). This is correctly set — no action needed, just verify no regression when a real video src is wired.

## What the Code Gets Right

- Header: hamburger Sheet at `md:hidden`, full-width Book CTA inside Sheet — correct.
- StickyBookingBar: `md:hidden`, full-width button, `h-12` tap target — correct.
- All major grids use `grid-cols-1` as the mobile base — no naked multi-column grids.
- Hero CTA buttons: `flex-col sm:flex-row` — correct stacking.
- WeavingShowcase: `grid-cols-1 md:grid-cols-2` — correct.
- Footer: `grid-cols-1 md:grid-cols-4` — correct.
- `AlpacaCard` images: `sizes` prop correctly set for responsive srcset.
- No hardcoded pixel widths on content containers (only on UI primitives like dropdowns, which is acceptable).

## CAN'T DO WITHOUT HELP

These findings require a live device or browser DevTools to confirm:

1. **FareHarbor calendar widget actual mobile render** — the third-party embed replaces the DOM; only DevTools can show what it actually injects at 375px.
2. **StickyBookingBar + CookieConsent overlap** — whether the two fixed elements actually collide depends on computed heights, which vary by content and locale. Needs device-level scroll test.
3. **Turnstile widget on 320px** — Cloudflare Turnstile renders an iframe; its minimum width is undocumented. Needs real render to verify it doesn't overflow.

5. **Orientation change (portrait → landscape)** — hero `min-h` and sticky bar z-stacking should be verified on landscape 375x667px (iPhone SE landscape).
