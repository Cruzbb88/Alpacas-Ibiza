## Part 2 — New Mobile Issues (components added since 2026-05-27)

### M-01 — MobileStickyBookingBar: dismiss `<button>` tap target is 32×32px (below 44×44px minimum) — HIGH
**File:** `components/mobile-sticky-booking-bar.tsx:232-245`
**Code:**
```tsx
className="shrink-0 inline-flex items-center justify-center h-8 w-8 rounded-full ..."
```
`h-8 w-8` = 32×32px. The WCAG 2.5.5 (AA) minimum is 44×44px for pointer targets. The primary CTA `<a>` at line 215 uses `min-h-[44px]` — correct. The dismiss `X` button is 12px under-height. On touch screens with a fat finger, the adjacent CTA's tap area overlaps the dismiss button's effective region.
**Fix:** Change `h-8 w-8` to `h-11 w-11` (44px) and compensate visually with a smaller icon if needed. Alternatively add `p-3` to push effective touch area to ≥44px.
**WCAG:** 2.5.5 Target Size

### M-02 — AlpacaPicker: tile grid `grid-cols-3` at 360px results in ~110px tiles — MEDIUM
**File:** `components/adopt/alpaca-picker.tsx:83`
**Code:**
```tsx
<div className="grid grid-cols-3 sm:grid-cols-4 md:grid-cols-5 lg:grid-cols-7 gap-3">
```
At 360px viewport: `(360 - 2×16px padding - 2×gap) / 3 ≈ 108px` per tile. Each tile has `min-h-11` (44px) applied, so tap height is met. Width ≥44px is also met at 108px. However with `p-3` (12px padding) on each tile, the inner content area shrinks. The alpaca photo (`w-10 h-10` = 40px) inside each tile risks being the only interactive area if the tile border is missed. This is heuristic — not a hard failure but worth noting for crowded 14-tile grids.
**Severity:** MEDIUM-LOW (heuristic). Functionally accessible.

### M-03 — AdoptGiftAdoption form: `<input type="date">` does not guarantee ≥16px font-size on iOS (prevents auto-zoom) — MEDIUM
**File:** `components/adopt/adopt-gift-adoption.tsx:215-221`
**Code:**
```tsx
<input type="date" ... className="w-full rounded-lg border border-border bg-background px-3 py-2 text-sm ..." />
```
`text-sm` = 14px. On iOS Safari, any input with `font-size < 16px` triggers automatic zoom-in on focus (the browser zooms to make the text readable). This is especially pronounced for `type="date"`. After dismissing the keyboard, the viewport stays zoomed. Since MA-001's F-01 (userScalable: false) has been fixed, the viewport is now scalable — but the auto-zoom on 14px inputs creates a jarring UX on the gift adoption flow.
The name/email text inputs at lines 174/189 also use `text-sm`.
**Fix:** Add `text-base` (16px) to all form inputs on the adopt gift section, or create a mobile-conditional `sm:text-sm text-base` utility.
**WCAG/Mobile:** Not a WCAG failure per se, but iOS UX anti-pattern that affects perceived quality.

### M-04 — AdoptGiftAdoption: `<details>/<summary>` pattern may have suboptimal tap-target height — LOW
**File:** `components/adopt/adopt-gift-adoption.tsx:144-145`
**Code:**
```tsx
<summary className="... px-5 py-4 ...">
```
`py-4` = 16px vertical padding. With `text-sm sm:text-base` content, the tap target height is approximately 16+16+20 = ~52px. This passes 44px. The `list-none` on summary removes the browser-default disclosure triangle but preserves the clickable area. Adequate.
**Severity:** PASS (documented for completeness).

### M-05 — PaymentHistoryTable: no `overflowX: 'auto'` on the outer section (only on inner div) — MEDIUM
**File:** `components/donor-portal/payment-history-table.tsx:130`
**Code:**
```tsx
<div style={{ overflowX: 'auto' }}>
  <table ...>
```
The `overflowX: 'auto'` is correctly applied on the div wrapping the table. The outer `<section>` has `padding: 20` on both sides. On a 360px viewport: `360 - 40px padding = 320px` of usable width. The table has 4 columns with `whiteSpace: 'nowrap'` on Date, Amount, and Method cells. The date column ("02 Jun 2026") + amount ("75.00 EUR") + status badge + method ("SEPA") comfortably fits in 320px because none of the `nowrap` content is particularly long. The horizontal scroll on the inner div is a backstop that works correctly. PASS — but the inner div scroll does not show a scrollbar indicator on iOS (Safari hides scrollbars). At runtime on a real device the user must discover swipe-to-scroll by accident.
**Severity:** LOW heuristic. Document for device testing.

### M-06 — my-adoption page: subscription `<dl>` with `gridTemplateColumns: '140px 1fr'` at 360px viewport — MEDIUM
**File:** `app/[locale]/my-adoption/page.tsx:235`
**Code:**
```tsx
<dl style={{ display: 'grid', gridTemplateColumns: '140px 1fr', gap: '8px 16px', fontSize: 14 ... }}>
```
At 360px viewport with `padding: '32px 16px'` on the parent `<main>`: usable width = 360 - 32 = 328px. The `<dl>` takes full width inside the section (padding: 20px each side of section) = 288px. The `140px` fixed column for labels takes 140/288 = 48.6% of the available width. The value column gets ~132px. Long values like "1 / month" or "01 Jun 2026" fit, but unusual subscription intervals or long currency names could overflow. Heuristic: acceptable for current data, but monitoring recommended.
**Severity:** LOW heuristic. No fix required unless long values are confirmed by device testing.

### M-07 — GreetingCardPicker: `grid-cols-3` at 360px results in ~100px card width — LOW
**File:** `components/adopt/greeting-card-picker.tsx:70`
**Code:**
```tsx
<div className="grid grid-cols-3 gap-3">
```
At 360px with typical page padding (~32px total): usable width ≈ 328px. Three columns + two 12px gaps = (328 - 24) / 3 ≈ 101px per card. Each card has `p-2` (8px padding) leaving ~85px for the `aspect-[3/4]` card thumbnail. At 85px wide / 4:3 ratio = 113px tall. The card is tappable (no explicit `min-h` but button nature provides default). Touch target height would be 113+32px (label + padding) ≈ 145px total. Adequate. No fix required.
**Severity:** PASS.

### M-08 — Embedded Mollie checkout: 4-field card form at 360px — MEDIUM (heuristic)
**File:** `components/adopt/embedded-mollie-checkout.tsx:363-438`
The Mollie card form places all 4 card components in a `space-y-4` stack (full-width), with expiry + CVC in a `grid-cols-2` layout. The `grid-cols-2 gap-3` on the expiry/CVC row at line 388 produces two ~160px cells at 360px (assuming 20px section padding). Mollie SDK injects an iframe into each slot. The iframe minimum width is documented as 120px — both cells clear this at 160px. Heuristic: adequate but requires live device verification with real Mollie iframes.
**Severity:** MEDIUM heuristic (needs device verification).

### M-09 — campaign-banner-generic: `flex-col sm:flex-row` — adequate but CTA button has no `min-h` — LOW
**File:** `components/campaign-banner-generic.tsx:50, 62-65`
The campaign banner CTA button at line 62 uses `px-4 py-1.5 text-xs`. `py-1.5` = 6px. Total button height ≈ 6+6+16 = ~28px. Below the 44px minimum for primary tap targets. The campaign banner is activated by env var (off by default), but when live this is a touch-target failure.
**Fix:** Change `py-1.5` to `py-2.5` to reach ≈36px (still below 44px minimum) or `py-3` for ≈44px. Alternatively add `min-h-[44px]` and `items-center`.
**Severity:** MEDIUM — applies when campaign banner is live (env-gated).

### M-11 — MobileStickyBookingBar: `aria-hidden={isHidden ? 'true' : 'false'}` on a visible-but-translated region — LOW (mobile-specific)
**File:** `components/mobile-sticky-booking-bar.tsx:197`
When the bar is sliding in (`isHidden` = false), the transition starts while `aria-hidden="false"` is set. When hidden (`translate-y-full`), it has `aria-hidden="true"`. This is correct, but the `pointer-events-none` at line 203 is only applied when hidden — during the 300ms slide-out transition, `pointer-events-none` has already been applied but the element is still partly visible. This is cosmetic. The z-50 stacking is correct.
**Severity:** LOW / heuristic. No code fix required.
