## 4. Top 5 Actionable Additions

Listed by leverage (biggest coverage gain per effort):

### #1 — GitHub Actions CI workflow (CRITICAL, ~1 hour)
Zero competitors ship without a test CI gate. Currently tests pass only if run manually.  
Add `.github/workflows/ci.yml` that runs `npm test` on every push/PR with Node 22.  
No new deps required — the built-in runner already works.

### #2 — Playwright E2E smoke suite for the 3 critical user flows (~1 day)
All JS competitors (Cal.com, Vercel examples) ship Playwright. Three flows to cover:  
(a) Book-a-tour CTA → FareHarbor redirect, (b) Contact form submit → 200 + email, (c) Adopt-a-paca checkout → Stripe redirect.  
Install: `@playwright/test` only. No other framework change required.  
Gives end-to-end confidence for every deploy.

### #3 — Vitest migration + @testing-library/react for component tests (~2–3 days)
Used by 3 of 4 JS refs. The Node built-in runner has no watch mode, no JSDOM, no snapshot diffing.  
Migrating to Vitest unlocks: component tests (`TurnstileWidget`, `BookingButton`, `AdminDashboard`, form flows), watch mode for dev, snapshot tests for email HTML output, and coverage via `@vitest/coverage-v8`.  
The 22 existing `node:test` files are almost drop-in compatible (rename `from 'node:test'` → `from 'vitest'`).

### #4 — Coverage baseline + ratchet (~30 min after #3)
After Vitest is in place, add `vitest --coverage` to CI and store `coverage-summary.json` as a PR artifact.  
No target % needed yet — just establish a baseline so coverage can only go up.  
Cal.com pattern: `@vitest/coverage-v8` + `c8`.

### #5 — axe-core accessibility checks in Playwright tests (~2 hours after #2)
No competitor does this today, but it is a low-effort force multiplier.  
Install `@axe-core/playwright`, add a single accessibility scan to the homepage E2E test.  
The site uses shadcn/Radix primitives (already ARIA-compliant) so this is expected to pass immediately and become a regression guard.

## 5. Where Alpaca is Ahead of Competitors

### #1 — Security-first unit test coverage on every auth/payment guard
Alpaca has 22 tests covering `safeEqual()`, `escapeHtml()`, `sanitizeHeader()`, `rateLimit()`, `fetchWithTimeout()`, payment handler fail-quiet behavior, and XSS guards.  
None of the competitors show this level of systematic unit coverage for security primitives. Cal.com tests business logic; Vercel examples test UI rendering; alpaca tests the security surface.

### #2 — Dependency-injection pattern enabling hermetic unit tests without HTTP mocking
`handleStripeCheckoutCompleted()` accepts `sendEmail` + `now` as injected deps, making all 14 payment-handler tests hermetic (no MSW, no fetch intercept, no test DB).  
This is a more advanced testability pattern than anything visible in the reference codebases at the utility layer.

### #3 — Zero test framework dependencies = zero supply-chain attack surface in tests
The built-in `node:test` + `node:assert` runner has no transitive test-framework deps. Competitors carry 10–30 test devDependencies. This is a deliberate tradeoff that alpaca benefits from for its current scale, though it becomes a constraint at component-test layer (see gap #3 above).
