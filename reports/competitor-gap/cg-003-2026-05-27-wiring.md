# CG-003 — Component Wiring Gap Analysis
**Date:** 2026-05-27  
**Scope:** 4 wiring dimensions vs. Cal.com, Dub.co, Documenso, Twenty  
**Alpaca files studied:**
- `app/[locale]/tours/page.tsx`
- `components/booking-section.tsx`
- `app/api/availability/route.ts`
- `components/contact-form.tsx`
- `lib/hooks/use-form-submit.ts`
- `app/error.tsx`, `app/[locale]/error.tsx`, `app/global-error.tsx`
- `app/loading.tsx`, `app/[locale]/loading.tsx`

---

## 1. Reference repo findings

### Cal.com (`apps/web/app`)

**Server/client split:** Root layout is an async Server Component. Fetches locale, headers (`cf-ipcountry`), and translations on the server, then passes them as props into `<Providers>` (Client Component) and `<AppRouterI18nProvider>`. tRPC queries run inside Client Components via `@trpc/react-query`. No data is fetched in the root layout that could block the page; auth context is injected via providers.

**Error boundaries:** Two-layer: `error.tsx` (route-level, catches HTTP errors, runs `captureException` via Sentry, redacts with `redactError()`) and `global-error.tsx` (catches root layout throws, also Sentry-wired). Error handling is observability-connected at both levels.

**Loading:** `loading.tsx` at route-segment level. No global spinner — each feature area has its own `loading.tsx` file alongside its `page.tsx`.

**Mutations:** tRPC `.useMutation()` with React Query's `onMutate` / `onError` / `onSettled` for optimistic rollback. Rate-limiting at handler level (`checkRateLimitAndThrowError`).

---

### Dub.co (`apps/web/app/app.dub.co`)

**Server/client split:** Dashboard uses a `page.tsx` (thin Server Component) + `page-client.tsx` (full Client Component) split for every major route. Server component does auth/session check; client component owns all SWR data fetching. Pattern is explicit: `page.tsx` just renders `<WorkspaceLinksClient />`.

**Error boundaries:** `error.tsx` exists at dashboard level but not confirmed at sub-route level. Relies partly on SWR's built-in error state (`data`, `error`, `isLoading` destructured from `useLinks()`).

**Loading:** `loading.tsx` at dashboard level re-exports `layout-loader` (a `LoadingSpinner` centered in `h-[calc(100vh-16px)]`). Per-route: SWR `isLoading` drives inline skeleton placeholders inside client components (e.g., folder permission loading → skeleton filter row in `WorkspaceLinksClient`).

**Mutations:** SWR `mutate()` for optimistic updates. Custom hooks (`useLinks`, `useFolderPermissions`) abstract SWR calls. Access control gates `canCreateLinks` before allowing mutation; trial-limit modal fires on quota breach. No Server Actions — all mutations go through API routes.

---

### Documenso (`apps/web/src/app`)

**Server/client split:** Monorepo with tRPC + Prisma. Auth is RSC-first — `(dashboard)` group checks session server-side. PDF operations (react-pdf, pdf-lib) stay server-side. Client components handle form state for signing flows.

**Error boundaries:** Architecture confirmed (route groups with layout files) but raw `error.tsx` files were not publicly accessible via raw fetch (404). Pattern inferred: tRPC error handling + route-level error boundaries per app-router convention.

**Loading:** No raw file accessible, but route-group structure (`(dashboard)`, `(unauthenticated)`) implies per-group `loading.tsx` files. PDF rendering is streaming-capable.

**Mutations:** Server Actions confirmed as primary mutation path for signing/document operations. tRPC mutations for workspace/settings. HMAC validation on critical paths.

---

### Twenty (`packages/twenty-front/src`)

**Server/client split:** SPA (Vite, not Next.js). All data fetching is client-side via Apollo (`useQuery`, `useLazyQuery`). Not directly comparable to alpaca's App Router model but useful for Apollo patterns.

**Error boundaries:** `useHandleFindManyRecordsError` hook processes Apollo errors uniformly. `onError` callbacks passed to query hooks for local error UI.

**Loading:** Dedicated `loading/components/` directory with reusable loading states. `useFindManyRecords` exposes `loading` boolean directly. Virtualization (`virtualization/`) handles large list perceived performance.

**Mutations:** Apollo `useMutation` with optimistic response via `optimisticResponse` field and `update` cache function. Permission checks (`hasReadPermission`) guard queries before execution.

## 3. Five specific improvements (file:line targets)

### #1 — Shape-matched per-route loading skeletons (HIGH leverage)

**Problem:** `app/[locale]/loading.tsx` fires for every route under `[locale]`. The 6×h-48 grid is a lie for the tours page (which has a hero + cards + timeline + FAQ + booking widget), contact page (single column form), gifts page (hero + single CTA), etc.

**Fix:** Add per-route `loading.tsx` files. Start with the two highest-traffic routes:

```
app/[locale]/tours/loading.tsx       ← new file
app/[locale]/contact/loading.tsx     ← new file
```

`app/[locale]/tours/loading.tsx` sketch:
```tsx
import { Skeleton } from '@/components/ui/skeleton'

export default function ToursLoading() {
  return (
    <div className="container mx-auto px-4 py-16" aria-busy="true">
      {/* Hero shape */}
      <Skeleton className="h-14 w-2/3 mx-auto mb-4" />
      <Skeleton className="h-6 w-1/2 mx-auto mb-12" />
      {/* Tour type cards — matches 4-column Features grid */}
      <div className="grid grid-cols-1 md:grid-cols-2 lg:grid-cols-4 gap-6 mb-16">
        {[0,1,2,3].map(i => <Skeleton key={i} className="h-64 w-full rounded-xl" />)}
      </div>
      {/* Booking widget placeholder */}
      <Skeleton className="h-96 w-full max-w-2xl mx-auto rounded-xl" />
    </div>
  )
}
```

Also update `app/[locale]/loading.tsx` to remove the card grid (it's misleading) and replace with a single centered skeleton that matches no specific page — or delete it and rely on per-route files.

**Competitor reference:** Dub's `apps/web/app/app.dub.co/(dashboard)/loading.tsx` (layout-level spinner) + inline SWR skeletons per feature. Cal.com: per-segment `loading.tsx` files throughout `(use-page-wrapper)/`.

### #2 — Observability hook in error boundaries (MEDIUM leverage)

**Problem:** `app/error.tsx` and `app/global-error.tsx` log `error.digest` to the browser console but do not send anything to an observability sink. Cal.com's `error.tsx` calls `captureException(error)` before rendering. Without this, production errors in the tours booking flow are invisible unless the user reports them.

**Fix:** `app/[locale]/error.tsx` lines 1–12 — add a `useEffect` that fires on mount to POST the digest to a lightweight `/api/log-error` route (or, if Sentry is ever added, `captureException`). Minimal version without Sentry:

```tsx
// app/[locale]/error.tsx
'use client'
import { useEffect } from 'react'

export default function Error({ error, reset }: { error: Error & { digest?: string }; reset: () => void }) {
  useEffect(() => {
    // Cheap server-side logging without Sentry dependency
    if (error.digest) {
      fetch('/api/log-error', {
        method: 'POST',
        headers: { 'Content-Type': 'application/json' },
        body: JSON.stringify({ digest: error.digest, url: window.location.pathname }),
      }).catch(() => {/* non-fatal */})
    }
  }, [error])
  // ... existing UI unchanged
}
```

The `/api/log-error` route writes to `console.error` server-side (Vercel captures it to Function Logs). Zero new dependencies.

**Competitor reference:** `apps/web/app/error.tsx` in Cal.com — `captureException(error)` via `@sentry/nextjs`.

### #3 — `BookingSection` client fetch: replace `animate-pulse` text with shape skeleton (MEDIUM leverage)

**Problem:** `components/booking-section.tsx` lines 96–100 — loading state is:
```tsx
<div className="text-center py-8 text-foreground/60">
  <div className="animate-pulse">{tr('bookingSection.loading')}</div>
</div>
```
This is a text string that pulses. No skeleton matches the 8-date grid that appears after load. Users see a layout shift (nothing → 8 date cards).

**Fix:** Replace with a skeleton grid that matches the actual date card layout:

```tsx
{loading && (
  <div className="grid grid-cols-2 md:grid-cols-4 gap-4 max-w-3xl mx-auto mb-8">
    {[0,1,2,3,4,5,6,7].map(i => (
      <Skeleton key={i} className="h-24 w-full rounded-xl" />
    ))}
  </div>
)}
```

`<Skeleton>` is already imported at `app/[locale]/loading.tsx` line 1 — add the same import to `booking-section.tsx`.

**Competitor reference:** Dub's `WorkspaceLinksClient` — SWR `isLoading` drives inline skeleton rows that match the actual link-item card dimensions.

### #4 — Sub-route error boundary for booking flow (LOW-MEDIUM leverage)

**Problem:** The single `app/[locale]/error.tsx` catches errors for all pages under `[locale]/`. If the FareHarbor calendar widget (`<FareHarborCalendar />`) throws during script injection, the entire tours page goes to the error boundary. A sub-route boundary at `app/[locale]/tours/error.tsx` would scope the error to just the tours segment and display a lighter "calendar unavailable" message rather than the full-page "something went wrong."

**Fix:** Create `app/[locale]/tours/error.tsx`:
```tsx
'use client'
export default function ToursError({ reset }: { reset: () => void }) {
  return (
    <div className="text-center py-16">
      <p className="text-foreground/70 mb-4">
        Our booking calendar is temporarily unavailable. Please try again or{' '}
        <a href="/en/contact" className="underline">contact us</a>.
      </p>
      <button onClick={reset} className="px-4 py-2 bg-primary text-white rounded-lg">
        Retry
      </button>
    </div>
  )
}
```

**Competitor reference:** Cal.com uses segment-level `error.tsx` alongside segment-level `page.tsx` throughout `(use-page-wrapper)/`.

### #5 — `startTransition` wrapper for `useFormSubmit` (LOW leverage, future-proof)

**Problem:** `lib/hooks/use-form-submit.ts` calls `setStatus('loading')` synchronously then awaits `fetch`. Under React 18 concurrent mode, UI updates inside an async chain without `startTransition` can produce tearing. Current behavior is fine because the form is simple (no concurrent features), but this becomes a problem if the form is ever placed inside a Suspense boundary.

**Fix:** Wrap the state transitions in `startTransition`:
```tsx
import { useTransition } from 'react'
// ...
const [isPending, startTransition] = useTransition()

const submit = async (e: React.FormEvent) => {
  e.preventDefault()
  startTransition(() => setStatus('loading'))
  // ... rest unchanged
}
```

**Competitor reference:** Cal.com uses `startTransition` around tRPC mutation state updates to prevent Suspense boundary interference.

## 4. One thing alpaca does that competitors don't

**`useFormSubmit` extraction is unusual — most projects don't do it.**

All three accessible competitors (Cal.com, Dub.co, Twenty) handle form mutations inline in the component: Cal.com uses `trpc.mutation.useMutation()` directly in the component, Dub uses SWR `mutate()` inline, Twenty uses Apollo `useMutation` inline. None extract a generic `idle/loading/success/error` state machine into a standalone hook.

Alpaca's `lib/hooks/use-form-submit.ts` is a reusable, typed, endpoint-agnostic hook that three forms (`contact-form.tsx`, `commission-form.tsx`, `newsletter-form.tsx`) consume identically. The `buildBody` callback pattern lets each form supply its own body shape without the hook knowing about form structure. This is closer to what you'd find in a headless form library (`react-hook-form`'s `handleSubmit` pattern) than in production app code.

The tradeoff: it abstracts away the flexibility to do optimistic updates per-mutation, but for alpaca's use case (fire-and-forget contact/commission/newsletter forms with no list to update), that flexibility is not needed and the hook reduces 3×~40 lines of boilerplate to 3×~8 lines.

## Summary: top 3 improvements by leverage

1. **Shape-matched per-route `loading.tsx`** — `app/[locale]/tours/loading.tsx` (new file). The `[locale]/loading.tsx` skeleton actively misleads users on every non-grid page. Highest visual-quality gap vs competitors.

2. **Observability in error boundary** — `app/[locale]/error.tsx` ~line 12. Silent error boundaries mean booking-flow failures are invisible in production. 5-line `useEffect` + `/api/log-error` fixes it with zero new dependencies.

3. **Skeleton grid in `BookingSection` loading state** — `components/booking-section.tsx` lines 96–100. Text-pulse → shape skeleton eliminates layout shift when the 8-date grid loads. Directly visible to every tours-page visitor.
