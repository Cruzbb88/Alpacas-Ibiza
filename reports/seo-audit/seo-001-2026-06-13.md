# SEO Correctness Audit — seo-001-2026-06-13

**Scope:** Alpacas Ibiza Next.js 16 redesign at `C:\Users\cruzb\Projects\alpaca-farm-redesign`
**Auditor:** SEO correctness pass — presence already confirmed vs competitors; this audits correctness and completeness only.
**Date:** 2026-06-13

---

## Executive Verdict

The SEO machinery is structurally sound — hreflang, canonical, and schema plumbing all exist — but carries **one catastrophic defect that must be resolved before launch**: the sitemap and `app/[locale]/layout.tsx` emit full hreflang alternates for de, es, fr, and it, while those four locales are **40.3% untranslated** (284 missing keys out of 704 total). Google will crawl German/Spanish/French/Italian pages that render English text (or raw i18n key strings) and interpret them as thin-content duplicates of the English pages, triggering duplicate-content demotion across all six locales. This is the single highest-risk SEO decision before launch. Fixing the JSON-LD schema and robots rules are secondary; the hreflang/thin-content call is primary.

## Thin-Content / Hreflang Risk Callout

**This is the highest-stakes SEO decision before launch.**

**Affected locales:** de, es, fr, it  
**Missing keys:** 284 out of 704 total (40.3%)  
**Source:** `reports/i18n/audit_raw.json:4–7`, `i18n.baseline.json:4–8`  
**nl is clean:** 0 missing keys — nl is safe to hreflang.

When Google crawls `/de/yoga`, `/de/sustainability`, `/de/workshops`, `/de/adopt`, `/de/weddings` (and 20+ more pages), it will find:
- UI text in English (from i18n fallback)
- OR raw key strings like `adopt.title` if next-intl has no fallback configured
- Full hreflang claims (`hreflang="de"`) asserting these are real German pages
- Canonical pointing to the same German URL

Google's duplicate-content algorithm will detect these German pages are near-identical to the English originals. The outcome is:
1. All six locales get a duplicate-content demotion signal
2. The German/Spanish/French/Italian pages rank for nothing (no German users, thin content)
3. The English pages lose ranking because they are now one of 5 near-duplicate versions

**Decision required before launch (OWNER-DATA):**

| Option | Recommendation |
|--------|----------------|
| A. Translate de/es/fr/it before launch | Best outcome. Complete the 284 missing keys. Only nl and en launch initially if translations take time. |
| B. Block de/es/fr/it from indexing now | Add `if (['de','es','fr','it'].includes(locale)) return { index: false }` in `app/[locale]/layout.tsx` `generateMetadata`. Remove them from sitemap `i18nConfig.locales` loop. Hreflang still emits but noindex prevents crawl. |
| C. Remove de/es/fr/it from hreflang until translated | Remove the 4 locales from `i18nConfig.locales` in sitemap.ts only for hreflang — complex to implement cleanly. |
| D. Launch with current state | **Not recommended.** Thin-content penalty affects all locales including en. |

**Recommended path:** Option B (noindex + sitemap exclusion) as an interim gate, then Option A as translations land per-locale. This lets the site launch with clean en/nl SEO while translations are completed.
