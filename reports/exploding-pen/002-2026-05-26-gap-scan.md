## Top 10 gaps + micro-gadgets

### 1. `withRetry` wrapper — leverage 9

- **Gap:** `lib/mailer.ts:sendEmail` and `lib/newsletter.ts:subscribe` call external APIs (Resend SDK, SendGrid) with zero retry. ep-001 identified this but did not design a gadget that works for both SDK calls and raw fetch. The two existing ep-001 designs (`lib/retry.ts` and a fetch-specific wrapper) are separate; a unified version is needed.
- **Gadget:** `lib/gadgets.ts`, 13 LOC

```typescript
/** Retries an async fn up to maxRetries with exponential backoff. */
export async function withRetry<T>(
  fn: () => Promise<T>,
  maxRetries = 3,
  baseMs = 150,
): Promise<T> {
  for (let attempt = 0; attempt <= maxRetries; attempt++) {
    try { return await fn() }
    catch (err) {
      if (attempt === maxRetries) throw err
      await new Promise(r => setTimeout(r, baseMs * 2 ** attempt))
    }
  }
  throw new Error('unreachable')
}
```

- **Wire-up:** Wrap `resend.emails.send(...)` in `sendEmail` (1 call site) + `fetch(url,...)` in `subscribe` (1 call site). 2 callers, covers every outbound email path.
- **Why not yet:** ep-001 proposed two separate modules; this consolidates into one canonical gadget file matching the existing `lib/fetch.ts` single-responsibility pattern.
- **Test:** Mock fn to throw twice, succeed on 3rd call. Assert result returned, delay called exactly twice.

### 2. `isValidEmail` utility — leverage 8

- **Gap:** `/api/contact`, `/api/commission`, and `/api/newsletter` accept user-supplied email with presence-only checks. The email regex already exists in `lib/webhook-router.ts:114` but is not shared. ep-001 proposed `lib/validators.ts` — this gadget delivers the strict-TypeScript type-narrowing version.
- **Gadget:** `lib/gadgets.ts`, 8 LOC (additive to same file)

```typescript
/** Type guard: returns true if value is a plausible email address. */
export function isValidEmail(value: unknown): value is string {
  return (
    typeof value === 'string' &&
    /^[^\s@]+@[^\s@]+\.[^\s@]{2,}$/.test(value.trim())
  )
}
```

- **Wire-up:** Replace bare `!email` in `/api/contact` (1), `/api/commission` (1), `/api/newsletter` (1). 3 callers. The regex is identical to `webhook-router.ts:114` — no invention.
- **Why not yet:** The regex was written inline for the webhook path and never extracted to a shared util.
- **Test:** Assert `isValidEmail('')` → false, `isValidEmail('bad')` → false, `isValidEmail('a@b.com')` → true (type-narrowed to `string`).

### 3. `getRequestId` middleware — leverage 7

- **Gap:** Zero request-ID threading across any of the 6 API routes. `console.error` calls have no correlation handle. When `sendEmail` fails inside `/api/contact`, there is no way to match the log line to the originating HTTP request in Vercel logs.
- **Gadget:** `lib/gadgets.ts`, 10 LOC (additive)

```typescript
import type { NextRequest, NextResponse } from 'next/server'
/** Injects a request ID into response headers; returns it for log threading. */
export function attachRequestId(
  req: NextRequest, res: NextResponse
): string {
  const id = req.headers.get('x-request-id') ?? crypto.randomUUID()
  res.headers.set('x-request-id', id)
  return id
}
```

- **Wire-up:** Add to `middleware.ts` (1 file, runs on every request). Each route handler reads `request.headers.get('x-request-id')` and prefixes its `console.error` calls. 6 route files benefit immediately.
- **Why not yet:** `middleware.ts` is i18n-only; observability was never layered in.
- **Test:** Send request without header; assert response has `x-request-id` matching UUID format.

### 5. `useAriaStatus` hook — leverage 7

- **Gap:** `BookingSection`, `GoogleReviewsBadge`, and `AvailabilityUrgency` all load data async and update the DOM silently. `aria-live` is used in `cookie-consent.tsx` but not on any data-fetching widget. Screen readers get no feedback when availability dates or the review badge appear.
- **Gadget:** `lib/gadgets.ts`, 14 LOC (additive)

```typescript
import { useRef, useEffect } from 'react'
/** Returns a ref for a sr-only aria-live region that announces on message change. */
export function useAriaStatus(message: string | null) {
  const ref = useRef<HTMLDivElement>(null)
  useEffect(() => {
    if (!ref.current || !message) return
    ref.current.textContent = ''
    requestAnimationFrame(() => {
      if (ref.current) ref.current.textContent = message
    })
  }, [message])
  return ref
}
// Render: <div ref={ref} aria-live="polite" aria-atomic="true" className="sr-only" />
```

- **Wire-up:** `BookingSection` (1), `GoogleReviewsBadge` (1), `AvailabilityUrgency` (1) — 3 callers. The component pattern is identical across all three; one hook covers all.
- **Why not yet:** Accessibility was addressed for navigation (skip-link exists in layout) but never applied to async-rendered widgets.
- **Test:** Render with `message="3 dates available"`; assert `aria-live` div textContent equals that string after next animation frame.

### 7. `useFormErrorAnnouncer` — leverage 6

- **Gap:** `ContactForm`, `CommissionForm`, and `NewsletterForm` all show error text visually on submission failure. None have `role="alert"` or `aria-live` on the error element, so screen reader users submitting the form get no feedback.
- **Gadget:** `lib/gadgets.ts`, 12 LOC (additive)

```typescript
import { useRef, useEffect } from 'react'
/** Returns a ref to an error element that auto-focuses screen readers on show. */
export function useErrorAnnouncer(isVisible: boolean) {
  const ref = useRef<HTMLParagraphElement>(null)
  useEffect(() => {
    if (isVisible && ref.current) ref.current.focus()
  }, [isVisible])
  return ref
}
// Render: <p ref={ref} role="alert" aria-live="assertive" tabIndex={-1}>…</p>
```

- **Wire-up:** `ContactForm` (1), `CommissionForm` (1), `NewsletterForm` (1) — 3 callers. All three share the same `status === 'error'` conditional pattern.
- **Why not yet:** Forms share the `useFormSubmit` hook but the error container's accessibility props were never standardized.
- **Test:** Simulate failed submit; assert element with `role="alert"` is in document; assert it receives focus.

### 9. `makeClientCache` factory — leverage 4

- **Gap:** `lib/use-availability.ts` implements a module-level promise cache with TTL. `GoogleReviewsBadge` fires a new `fetch('/api/google-reviews')` on every mount with no equivalent dedup. If the badge appears in multiple positions on a page, it fires duplicate requests. The `useAvailability` cache pattern should be generalised.
- **Gadget:** `lib/gadgets.ts`, 13 LOC (additive)

```typescript
/** Creates a module-level promise cache for a single async resource with TTL. */
export function makeClientCache<T>(
  fetcher: () => Promise<T>,
  ttlMs: number,
): () => Promise<T> {
  let cached: Promise<T> | null = null
  let cachedAt = 0
  return (): Promise<T> => {
    if (cached && Date.now() - cachedAt < ttlMs) return cached
    cachedAt = Date.now()
    cached = fetcher().catch(e => { cached = null; throw e })
    return cached
  }
}
```

- **Wire-up:** New `lib/google-reviews-cache.ts` (3 lines): `export const fetchReviews = makeClientCache(() => fetch('/api/google-reviews').then(r => r.json()), 6 * 3600 * 1000)`. `GoogleReviewsBadge` imports it (1 caller). `useAvailability` can be refactored to use it (1 more caller) making the pattern canonical.
- **Why not yet:** `GoogleReviewsBadge` was written as a standalone component; the availability cache was never abstracted.
- **Test:** Call cache fn twice in < TTL; assert fetcher invoked once.

### 10. `narrowFHTypes` — eliminate `any` in availability route — leverage 4

- **Gap:** `app/api/availability/route.ts` uses `(item: any)`, `(itemPk: any)`, and `(avail: any)` — 4 cast sites. TypeScript strict mode is subverted. The FareHarbor API shape is already partially typed in `lib/webhook-router.ts` (`FareHarborBooking`). The availability route's narrower shape is derivable.
- **Gadget:** `lib/gadgets.ts`, 14 LOC (additive)

```typescript
/** Minimal FareHarbor shapes for the availability endpoint. */
export interface FHItem { pk: number }
export interface FHAvail { start_at: string; capacity: number }
export function isFHItem(v: unknown): v is FHItem {
  return typeof v === 'object' && v !== null &&
    typeof (v as FHItem).pk === 'number'
}
export function isFHAvail(v: unknown): v is FHAvail {
  return typeof v === 'object' && v !== null &&
    typeof (v as FHAvail).start_at === 'string' &&
    typeof (v as FHAvail).capacity === 'number'
}
```

- **Wire-up:** Replace 4 `any` casts in `app/api/availability/route.ts` using these guards + filter. Also eliminates 1 `any` in `app/api/google-reviews/route.ts`. 2 files.
- **Why not yet:** FareHarbor types were first modelled for the webhook shape; the availability route was written independently and never shared the type definitions.
- **Test:** Pass `{ pk: 'string' }` to `isFHItem`; assert false. Pass `{ pk: 42 }`; assert true.

## STOP

Gadgets that cannot be designed without owner intent:

- **SendGrid list segmentation** — whether a second list (e.g. "tour inquirers" vs "newsletter subscribers") is needed is a business decision; can't design the split without knowing the owner's email strategy.
- **Resend idempotency keys on retry** — Resend supports idempotency keys to prevent duplicate sends on retry, but this is a paid-tier feature. Don't add without confirming plan.
- **Rate-limit shared state upgrade** — moving `rateLimit` to Redis/Vercel KV for multi-instance correctness requires an infrastructure decision. ADR 001 explicitly defers this; don't design without owner sign-off.
