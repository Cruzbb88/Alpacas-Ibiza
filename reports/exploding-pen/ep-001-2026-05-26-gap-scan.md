### #8 — G-07 · Add a 1-retry wrapper around `fetchWithTimeout`
**File target:** `lib/fetch.ts`  
**Impact:** Reliability — single transient FareHarbor error currently hides availability widget for full 2h cache. One retry on non-4xx drops this rate to near zero.  
**Estimated time:** 10 min

```ts
export async function fetchWithRetry(
  url: string,
  init: RequestInit = {},
  ms = 5000,
  retries = 1,
): Promise<Response> {
  try {
    return await fetchWithTimeout(url, init, ms)
  } catch (err) {
    if (retries > 0) return fetchWithRetry(url, init, ms, retries - 1)
    throw err
  }
}
```
Then update `app/api/availability/route.ts` to use `fetchWithRetry` instead of `fetchWithTimeout` for the FareHarbor calls.
