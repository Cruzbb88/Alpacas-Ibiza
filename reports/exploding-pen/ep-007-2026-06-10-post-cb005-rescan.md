## L2 — gadget design (score 100/100)

### gd-021 — `donorReceiptTokenAudit`

**Category:** Logging/observability
**Pattern:** call-site inline log
**Lines:** 6
**Target:** [`app/api/donor-receipt/[sessionId]/route.ts:99-104`](app/api/donor-receipt/%5BsessionId%5D/route.ts#L99-L104)

```typescript
console.warn('[donor-receipt] token reject', {
  reason: token === '' ? 'missing' : 'invalid',
  sessionIdSuffix: sessionId.slice(-6),
})
```

**Rationale:** Server-side log distinguishes "no token sent" (scanner / direct probe / not-yet-wired caller) from "token invalid" (replay attempt, expired, wrong scope, sessionId mismatch). Response remains uniform 404 (anti-oracle). `sessionIdSuffix` (last 6 chars) lets ops correlate with Stripe/Mollie dashboards without logging the full ID.

**Status:** Injected ✓

### gd-022 — `donorReceiptTokenContract` (test gadget)

**Category:** Input validation (test-coverage flavour)
**Pattern:** sibling `.test.ts` mirroring `lib/newsletter-token.test.ts`
**Lines:** 87 (test file)
**Target:** [`lib/donor-receipt-token.test.ts`](lib/donor-receipt-token.test.ts) (new)

**Locks:**
1. Sign + verify roundtrip
2. sessionId binding (token signed for A fails when verified for B)
3. Tampered signature → null
4. Expired token → null
5. **Scope-guard** — a valid `mollie-manage` cancel-scope token does NOT verify at donor-receipt scope (prevents cross-use IDOR)
6. Oversized 2049-byte input → null (DoS guard fires before HMAC compute)
7. Empty / malformed → null
8. Default TTL is 60 days

**Rationale:** The donor-receipt token is the only thing standing between an attacker holding a `cs_*`/`tr_*`/`sub_*` ID and the donor's PII PDF. Sibling security primitives (`newsletter-token`, `mollie-manage-token`) both have contract tests; this one was missing them. Locks the security boundary against drift.

**Status:** Injected ✓ (tsc clean)
